# Cadence Platform

The deployment configuration for [Cadence](https://github.com/cadence-muse), a shared repertoire manager for musical bands.
It defines the production Kubernetes workloads, data services, ingress, secrets, and release sequence.

## 🎯 Responsibilities

- Deploy the Cadence API and web client from GHCR images
- Run PostgreSQL and Redis with persistent storage
- Route web and API traffic through Traefik
- Apply database migrations before application rollouts
- Encrypt production credentials with SOPS and age

## 🏗️ Architecture

```text
k8s/base/                    reusable Kubernetes resources
k8s/base/cadence-server/     API deployment, service, PDB, and migration job
k8s/base/cadence-client/     web client deployment, service, and PDB
k8s/base/postgres/           PostgreSQL deployment, service, and volume
k8s/base/redis/              Redis deployment, service, and volume
k8s/prod/                    production ingress, image tags, and secrets
```

Kustomize composes the base into the `cadence` namespace. Traefik sends `/api` requests to the Go service
and all other requests to the Flutter web client. Configuration comes from a ConfigMap; credentials come
from a SOPS-encrypted Secret generated by ksops.

## 🛠️ Local validation

### Prerequisites

- `kubectl` with Kustomize support
- [kubeconform](https://github.com/yannh/kubeconform)
- `kustomize`, `ksops`, `sops`, and `age` for the production overlay

Validate the reusable base without access to production secrets:

```shell
kubectl kustomize k8s/base > rendered.yaml
kubeconform --strict --summary --ignore-missing-schemas rendered.yaml
```

Render the production overlay when `SOPS_AGE_KEY` is available:

```shell
kustomize build --enable-alpha-plugins --enable-exec k8s/prod
```

## ⚙️ Configuration

Non-secret service settings live in [`k8s/base/configmap.yaml`](k8s/base/configmap.yaml),
including PostgreSQL and Redis addresses, connection limits, session policy, and allowed browser origins.

Production image versions and resources are assembled in [`k8s/prod/kustomization.yaml`](k8s/prod/kustomization.yaml).
Update the `newTag` for the API or client image to deploy a new release.

Secret values live in `k8s/prod/secret.enc.yaml`. The `.sops.yaml` policy encrypts `data` and `stringData` values for the project's age recipient.

```shell
sops k8s/prod/secret.enc.yaml
```

Keep decrypted credentials out of the repository.

## 🗃️ Migrations

The `cadence-migrate` Job runs the API image in `migrate` mode. Deployment automation applies prerequisites first,
waits for PostgreSQL and Redis, recreates and waits for the migration Job, then applies the remaining workloads.
A failed migration stops the rollout.

Do not apply application deployments ahead of their required migration.
Database migration files themselves belong in the [`cadence`](https://github.com/cadence-muse/cadence) repository.

## 🚀 Deployment

Production deploys are manual through the `Apply Kubernetes Manifests` GitHub Actions workflow. The environment requires:

- `KUBECONFIG`: access to the target cluster
- `SOPS_AGE_KEY`: the private key that decrypts the production Secret

For an authorized operator, the equivalent direct apply is:

```shell
kustomize build --enable-alpha-plugins --enable-exec k8s/prod \
  | kubectl apply -f -
```

The workflow is preferred because it enforces migration ordering and waits for each rollout.
